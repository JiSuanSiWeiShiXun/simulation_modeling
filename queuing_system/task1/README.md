# 麦当劳排队系统模拟 (McDonald's Queuing System Simulation)

## 题目描述 (Problem Description)

本作业旨在模拟麦当劳的服务窗口和取餐窗口的排队系统。模拟重点关注顾客在两个关键服务点的流动：点餐付款的服务窗口和取餐的取餐窗口。通过模拟来估计运营指标，如顾客等待时间和服务效率。

```
顾客到达 → [服务窗口 G₁] → [取餐窗口 G₂] → 离开
Arrivals   (点餐付款)      (领取食物)    Departures
          (Order & Pay)   (Food Pickup)
```

### 系统结构 (System Structure)

麦当劳排队系统由两个串联的服务器组成：

- **服务窗口 (Server 1, G₁)**: 顾客在此点餐并付款
- **取餐窗口 (Server 2, G₂)**: 顾客在此领取食物
- **流程**: 顾客必须先在 G₁ 完成服务，然后才能前往 G₂

### 系统参数 (System Parameters)

| 参数 | 数值 | 分布类型 |
|------|------|----------|
| **顾客到达率** | 平均 21 人/小时 | 泊松过程 (Poisson Process) |
| **服务窗口服务时间** | 均值 = 0.03 小时 (1.8 分钟) | 指数分布 (Exponential) |
| **取餐窗口服务时间** | 均值 = 0.05 小时 (3.0 分钟) | 指数分布 (Exponential) |
| **营业时间** | 上午10:00 - 晚上8:00 | 共10小时 |

## 任务要求 (Task Requirements)

### Task a) 模拟2小时运营

**目标**: 模拟麦当劳排队系统2小时的运营，并记录顾客流动详情

**输出要求**:

- 显示至少 30 位顾客在每个服务器的到达和离开时间
- 记录每位顾客的以下信息：
  - 到达系统的时间
  - 在服务窗口 (G₁) 的开始和结束时间
  - 在取餐窗口 (G₂) 的开始和结束时间
  - 在系统中的总时间

**交付成果**:

- 事件驱动模拟实现
- 显示时间戳的顾客记录表
- 顾客流动的可视化表示

### Task b) 估计顾客在系统中的期望时间

**目标**: 使用模拟来估计顾客在系统中停留的期望时间（模拟到 t=10 小时）

**方法**:

- 模拟系统运营 10 小时
- 跟踪所有进入并完成服务的顾客
- 计算每位顾客在系统中的平均总时间
- 运行100次重复模拟以获得置信区间

**需要计算的指标**:

- 系统中的平均时间（端到端）
- 在服务窗口的平均等待时间
- 在取餐窗口的平均等待时间
- 平均服务器利用率

### Task c) 估计所需加班时间

**场景描述**:

- 营业时间：上午 10:00 - 晚上 8:00（共10小时）
- 晚上 8:00 之后，**不再接受新顾客进入**
- 但是，必须为所有已经在系统中的顾客完成服务

**目标**: 估计服务器完成为所有剩余顾客服务所需的预期加班时间

**计算方法**:

```text
加班时间 = (最后一位顾客离开时间) - (关门时间 晚上8:00)
```

**关键考虑因素**:

- 晚上 8:00 前到达的顾客允许完成服务
- 服务窗口和取餐窗口都必须完成为所有排队顾客的服务
- 加班时间在最后一位顾客离开系统时结束

## 理论基础 (Theoretical Background)

### 泊松到达过程 (Poisson Arrival Process)

顾客到达遵循泊松过程，到达间隔时间服从指数分布：

**齐次泊松过程（标准模型）**:

```r
# 全天到达率恒定
到达间隔时间 ~ Exponential(λ = 21 顾客/小时)
```

**非齐次泊松过程（考虑高峰时段）**:

```r
到达率 λ(t) 随时间变化：
- 早餐高峰 (10:00-11:30): λ ≈ 25-30 人/小时
- 午餐高峰 (11:30-13:30): λ ≈ 40-50 人/小时
- 非高峰 (14:00-17:00): λ ≈ 5-10 人/小时
- 晚餐高峰 (17:00-19:00): λ ≈ 45-50 人/小时
- 平均到达率保持 21 人/小时
```

### 指数服务时间 (Exponential Service Times)

两个服务窗口的服务时间都服从指数分布：

```r
服务窗口服务时间 ~ Exponential(μ₁ = 1/0.03 = 33.33 顾客/小时)
取餐窗口服务时间 ~ Exponential(μ₂ = 1/0.05 = 20 顾客/小时)
```

### 排队论指标 (Queueing Metrics)

- **等待时间 (Waiting Time)**: 顾客到达到开始服务的时间
- **服务时间 (Service Time)**: 实际接受服务的时间
- **系统时间 (Time in System)**: 从到达到离开的总时间 = 等待时间 + 服务时间
- **利用率 (Utilization)**: 服务器忙碌的时间比例

## 关键发现

通过模拟分析可以得出：

### 齐次泊松过程（传统模型）
1. **系统瓶颈**: 取餐窗口（服务率20人/小时）比服务窗口（33.33人/小时）慢，可能成为系统瓶颈
2. **平均等待时间**: 顾客在取餐窗口的等待时间通常长于服务窗口
3. **加班必要性**: 由于顾客随机到达和服务时间的随机性，通常需要一定的加班时间
4. **系统稳定性**: λ = 21 < μ₂ = 20，系统处于临界状态，长期运行可能不稳定

### 非齐次泊松过程（考虑饭点高峰）
1. **更真实的模拟**: 到达率随时间变化，更符合实际餐饮场景
2. **高峰期压力**: 
   - 午餐和晚餐高峰期，系统压力显著增大
   - 平均系统时间比齐次模型增加 **50-60%**
   - 平均等待时间增加 **60-70%**
3. **峰谷差异明显**:
   - 高峰期到达率可达 40-50 人/小时（超过取餐窗口处理能力）
   - 非高峰期仅 5-10 人/小时
   - 峰谷比约 **6-7 倍**
4. **管理启示**:
   - 需要动态调整人员配置
   - 高峰期可能需要增加服务窗口
   - 可通过优惠引导顾客错峰就餐
